# 概念 1：科研工程生存包

## 虚拟环境隔离原理

### 1. 一个 Python 环境由什么构成

一个完整的 Python 环境由两部分组成：

- **解释器**：Python 的可执行二进制文件（如 `python3.10`、`python3.11`），决定了 Python 版本和语言特性
- **包**：标准库 + 第三方包（存放在 `site-packages`），决定了环境能提供哪些额外功能

### 2. 代码运行时，解释器如何找到包

1. **Shell 根据 `PATH` 找到对应的 Python 解释器并启动它**
2. 解释器启动时，根据自身可执行文件的物理位置，自动推算出 `sys.prefix`（环境根目录，一个字符串，存在内存中的 `sys` 模块对象上，类似 `student.name` 的属性访问方式）
3. 解释器用 `sys.prefix` 拼接出包搜索路径，构建出 `sys.path` 列表，例如：
   ```
   ~/anaconda3/envs/cc/lib/python311.zip
   ~/anaconda3/envs/cc/lib/python3.11          # 标准库
   ~/anaconda3/envs/cc/lib/python3.11/lib-dynload  # C 扩展
   ~/anaconda3/envs/cc/lib/python3.11/site-packages  # 第三方包
   ```
4. 此后代码中的 `import numpy` 就会按 `sys.path` 从上到下搜索，找到的第一个就用

> `sys.path` 不是磁盘上的文件，而是解释器运行时在内存中动态构建的列表，每次启动解释器时自动生成。

### 3. venv：共享解释器，隔离包

venv 的隔离方式是"轻量级"的：

- **不复制 Python 解释器**，而是创建一个指向系统 Python 解释器的链接/副本
- 创建独立的 `site-packages` 目录和 `pyvenv.cfg` 配置文件
- 激活后修改 `PATH`，使 Shell 优先找到 venv 目录下的 Python 启动脚本
- 该启动脚本设置 `sys.prefix` 指向 venv 目录，从而让 `sys.path` 指向 venv 自己的 `site-packages`

**本质**：同一个解释器二进制，但通过不同的 `sys.prefix` 指向不同的包目录，实现包级别的隔离。类比——"同一栋楼里租了不同的房间"。

> 局限：因为解释器是共享的，所以 venv **只能使用系统已安装的 Python 版本**，无法切换版本。

### 4. conda：彻底隔离解释器与包

conda 的隔离方式是"重量级"的：

- **每个环境都安装自己独立的 Python 解释器二进制文件**（不同环境可以有不同版本，如 3.8/3.9/3.10/3.11）
- 每个解释器有自己独立的 `site-packages`，甚至还有独立的 C/C++ 库
- 激活时同样修改 `PATH`，使 Shell 找到该环境的解释器
- 该解释器根据自身位置推算出的 `sys.prefix` 自然指向该 conda 环境目录

**本质**：连解释器都换了，`sys.prefix`、`sys.path` 完全独立，实现解释器 + C 库 + 包的完整隔离。类比——"直接建了不同的楼"。

### 5. 激活操作到底做了什么

无论是 venv 还是 conda，`activate` 的核心动作就是**修改 `PATH` 环境变量**，把目标环境的 `bin/` 目录放到最前面。这样 Shell 执行 `python` 时，会优先找到该环境的解释器，解释器再根据自身位置推算出该环境的搜索路径。

完整的因果链：

```
conda activate cc
  → 修改 PATH，把 ~/anaconda3/envs/cc/bin/ 放最前
  → Shell 找到 ~/anaconda3/envs/cc/bin/python
  → Python 启动，根据自身位置算出 sys.prefix = ~/anaconda3/envs/cc/
  → 拼出 sys.path，指向该环境的 site-packages
  → import 时只搜索该环境的包，隔离完成
```

## 虚拟环境对比：venv vs conda

| 特性 | venv | conda |
|---|---|---|
| Python 版本 | 只能创建与系统安装的 Python 版本一致的虚拟环境 | 可创建任意 Python 版本的虚拟环境（如 `conda create -n env python=3.10`） |
| 包类型 | 只能安装 Python 包（PyPI 生态） | 既可安装 Python 包，也可安装 C/C++ 库及非 Python 依赖 |
| 常用可安装的 C 库 | 不支持 | `numpy`（含 BLAS/MKL 底层 C 库）、、`opencv`（含 C++ 原生库）等 |
| 适用场景 | 轻量级纯 Python 项目 | 需要跨语言依赖、多 Python 版本切换的科研/工程项目 |

## PATH 环境变量

`PATH` 是操作系统（Shell）的一个环境变量，不是文件，也不是 Python 的概念。它是一个用冒号 `:` 分隔的目录列表字符串，从左到右优先级从高到低。

### PATH 中通常记录什么

| 层次 | 示例路径 | 说明 |
|---|---|---|
| **用户级**（最前） | `~/.local/bin`、`~/anaconda3/envs/cc/bin`、`~/.nvm/.../bin` | 用户自己安装的工具、虚拟环境的 bin 目录 |
| **系统级**（中间） | `/usr/local/bin`、`/usr/bin`、`/bin`、`/usr/sbin`、`/sbin` | 操作系统自带的命令（`ls`、`cat`、`grep` 等） |
| **扩展级**（最后） | `/snap/bin`、`/usr/games`、`~/.dotnet/tools` | 包管理器或应用附带的工具 |

### PATH 如何工作

在终端输入任何命令时，Shell 都会按 `PATH` 从左到右逐个目录查找，找到第一个匹配的可执行文件就用它。例如：

- 输入 `python` → 先在 `~/anaconda3/envs/cc/bin/` 找到，就用它
- 输入 `ls` → `~/anaconda3/envs/cc/bin/` 里没有，继续往后，在 `/usr/bin/ls` 找到
- 如果所有目录都找不到 → 报 `command not found`

### 切换 Python 环境时 PATH 怎么变

切换环境时，修改的就是 `PATH` **最前面的第一个路径**——把目标环境的 `bin/` 目录插到最前，其余路径不变。由于 Shell 从左到右查找，最前面的优先级最高，所以 Shell 会优先找到该环境的 `python`。

### 如何修改 PATH

```bash
# 临时修改（仅当前终端有效）
export PATH="/my/custom/bin:$PATH"

# 永久修改（写入 ~/.bashrc，每次开终端自动生效）
echo 'export PATH="/my/custom/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

> conda/venv 的 `activate` 脚本本质上就是在执行 `export PATH="环境bin目录:$PATH"`，`deactivate` 时再把它撤掉。

## 相对路径与绝对路径

### 绝对路径

从**根目录 `/` 开始**的完整路径，无论你当前在哪个目录，同一个绝对路径永远指向同一个位置。

```
/home/xavier/暑期培训/01 python/学习记录.md
/usr/bin/python3
```

特点：唯一确定、不依赖当前位置，但换电脑/换用户后路径会失效。

### 相对路径

从**当前所在目录**开始算起的路径，用 `.`（当前目录）、`..`（上级目录）表示。

```
./学习记录.md          # 当前目录下的文件
../01 python/          # 上级目录中的文件夹
../../etc/passwd       # 往上两级再进入 etc
```

| 符号 | 含义 |
|---|---|
| `.` | 当前所在目录 |
| `..` | 上一级目录 |
| `~/` | 当前用户的 home 目录（如 `/home/xavier/`） |

## Python 内存模型与陷阱

### 1. Python vs C 的变量区别

| 特性 | C 语言 | Python |
|---|---|---|
| 变量本质 | 盒子，内存中分配一块空间，直接存值 | 标签（引用），贴在对象上，对象独立存在于堆内存 |
| 赋值 `b = a` | 把 a 的值复制一份到 b 的内存空间 | b 和 a 贴到同一个对象，没有复制新对象 |
| 修改 `b` | a 不受影响（各自独立的盒子） | a 可能受影响（如果对象是可变的） |
| 类型 | 静态类型，声明时确定 | 动态类型，随时可变 |

```python
# Python
a = [1, 2, 3]    # 内存中创建 list 对象 [1,2,3]，a 贴在它上面
b = a            # b 也贴到同一个对象上，没有创建新 list
b.append(4)     # 修改了那个对象
print(a)          # [1, 2, 3, 4] —— a 也变了，因为 a 和 b 指向同一个对象
```

### 2. 陷阱：可变对象作为默认参数

```python
def add_item(item, lst=[]):
    lst.append(item)
    return lst

print(add_item(1))  # [1]
print(add_item(1))  # [1, 1] —— 不是 [1]！
```

**原因**：函数定义时，默认参数 `[]` 只被创建一次，之后每次调用都复用同一个 list 对象。

**正确写法**：

```python
def add_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst
```

### 3. 容器的内外层概念

当容器（list/dict/set）内部还嵌套着可变对象时，就产生了内外层之分。**判断标准：你在操作哪个容器，就是哪一层。**

用 `[X, X]` 的形式理解：

- **外层操作**：`[X, X]` → `[X, X, X]`（外层 list 本身的元素增删改，长度或指向变了）
- **内层操作**：`[X, X]` 还是 `[X, X]`（外层不变），但某个 `X` 的内部内容变了

| 操作类型 | 代码示例 | 变化形式 | 说明 |
|---|---|---|---|
| 外层操作 | `a.append([5, 6])` | `[X, X]` → `[X, X, X]` | 外层 list 多了一个元素 |
| 外层操作 | `a[0] = [9, 9]` | `[X, X]` → `[Y, X]` | 外层第 0 个位置换成了新对象 |
| 内层操作 | `a[0].append(3)` | `[X, X]` 不变，但 `X` 内部变了 | 进入 `a[0]` 内部修改 |
| 内层操作 | `a[1][0] = 99` | `[X, X]` 不变，但 `X` 内部变了 | 进入 `a[1]` 内部修改 |

每多一层索引 `[]`，就深入一层。不可变对象（int、str、tuple）不存在内层操作问题，因为不能原地修改，只能重新赋值（创建新对象）。

**易混淆对比**：对于`a=[[0, 0], [0, 0]]`，`a[0] = [0, 1]` vs `a[0][1] = 1`，结果都是 `a` 变成 `[[0, 1], ...]`，但底层完全不同：

| 操作 | 层次 | 底层行为 | 浅拷贝是否受影响 |
|---|---|---|---|
| `a[0] = [0, 1]` | 外层 | 创建新对象 `[0, 1]`，让 `a[0]` 指向它，原对象被丢弃 | 不受影响（外层独立） |
| `a[0][1] = 1` | 内层 | 进入 `a[0]` 指向的原对象内部，原地修改 | **受影响**（内层共享） |

### 4. 浅拷贝、深拷贝与直接赋值的区别

```python
import copy

a = [[1, 2], [3, 4]]

b = a                    # 直接赋值
c = a.copy()             # 浅拷贝
d = copy.deepcopy(a)     # 深拷贝

a[0][0] = 99
```

| 方式 | 外层对象 | 内层对象 | a 变化后受影响？ |
|---|---|---|---|
| `b = a`（直接赋值） | 同一个引用 | 同一个引用 | 外层内层全受影响 |
| `c = a.copy()`（浅拷贝） | 新对象 | 同一个引用 | 内层受影响，外层不受 |
| `d = copy.deepcopy(a)`（深拷贝） | 新对象 | 新对象 | 完全不受影响 |

> 用电路类比：直接赋值像"同一块电路板，没动"；浅拷贝像"换了一根线，但线的两端还接着原来的元件"；深拷贝像"整个电路板重新焊了一遍，所有元件都是新的"。

## 图形化调试技巧（VS Code 断点调试）

用图形界面代替 `print()` 排查问题。在代码中设置断点，程序运行到断点处暂停，可查看所有变量值和调用栈，然后逐步执行观察变化。

| 快捷键 | 功能 | 说明 |
|---|---|---|
| `F5` | 启动调试 | 运行程序，遇到断点暂停 |
| `F10` | 单步跳过（Step Over） | 执行当前行，不进入函数内部 |
| `F11` | 单步进入（Step Into） | 执行当前行，进入函数内部 |
| `Shift+F11` | 单步跳出（Step Out） | 从当前函数跳出 |
| `F9` | 切换断点 | 设置/取消断点 |

- **条件断点**：右键断点圆点，设置条件表达式（如 `i == 50`），只有条件为 True 时才暂停
- 对比 `print` 调试：断点调试可暂停后查看所有变量，逐步执行观察变化，无需反复加删 print

## 导出 requirements.txt

`requirements.txt` 记录当前环境中所有第三方包及版本，用于在其他环境中复现相同依赖。

```bash
# 导出当前环境的所有包
pip freeze > requirements.txt

# 在新环境中一键安装
pip install -r requirements.txt
```

conda 环境也可用 conda 自己的格式：

```bash
conda env export > environment.yml       # 导出
conda env create -f environment.yml      # 复现
```

## pathlib.Path 库

`pathlib` 是 Python 3.4+ 标准库，`Path` 是核心类，用**面向对象方式**操作文件路径，替代传统的 `os.path` 字符串拼接。

```python
from pathlib import Path

# 创建路径对象
p = Path("data/sensor.csv")

# 路径拼接（用 / 运算符）
root = Path(".")
csv_file = root / "data" / "sensor.csv"

# 遍历目录下所有 .csv 文件
for f in Path("data").glob("*.csv"):
    print(f)
```

### 常用操作

| 操作 | pathlib | os.path |
|---|---|---|
| 拼接路径 | `Path("data") / "file.csv"` | `os.path.join("data", "file.csv")` |
| 判断是否存在 | `p.exists()` | `os.path.exists(path)` |
| 获取文件名 | `p.name` | `os.path.basename(path)` |
| 获取扩展名 | `p.suffix` | `os.path.splitext(path)[1]` |
| 获取父目录 | `p.parent` | `os.path.dirname(path)` |
| 创建目录 | `p.mkdir()` | `os.makedirs(path)` |
| 读取文件 | `p.read_text()` | `open(path).read()` |
| 写入文件 | `p.write_text("hi")` | `open(path, "w").write("hi")` |
| 遍历目录 | `Path("data").glob("*.csv")` | `os.listdir()` + 手动过滤 |

> 核心优势：路径是对象而非字符串，操作更直观；`/` 运算符自动处理跨平台路径分隔符（Windows `\` / Linux `/`）；内置读写方法减少样板代码。
