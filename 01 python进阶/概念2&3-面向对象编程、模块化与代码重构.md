# 概念 2：面向对象编程 (OOP)

## 类与对象的关系

类（Class）是蓝图/模板，对象（Object）是按蓝图造出来的实例。一个类可以创建无数个对象，每个对象有独立的属性值，但共享同一套方法定义。

```python
class Dog:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return f"{self.name}: 汪汪！"

d1 = Dog("旺财")    # d1 是对象（实例）
d2 = Dog("小黑")    # d2 是另一个对象
```

| 概念 | 说明 | 类比 |
|---|---|---|
| 类 | 定义了属性和方法的结构 | 电路原理图 |
| 对象 | 根据类创建的具体实例 | 按图纸焊好的电路板 |
| `__init__` | 对象创建时自动调用的初始化方法 | 出厂设置 |
| `self` | 指向当前对象自身的引用 | "我这个电路板" |

## 魔术方法与属性封装

### 常用魔术方法

魔术方法是 Python 以 `__双下划线__` 包裹的内置方法，让你自定义对象的内置行为（如 `len()`、`print()`、`[]` 索引等）。

```python
class DataBuffer:
    def __init__(self, data):
        self._data = data

    def __str__(self):           # print(buffer) — 用户友好显示
        return f"DataBuffer({len(self._data)} items)"

    def __repr__(self):          # 终端直接输入变量名 — 开发者调试
        return f"DataBuffer(data={self._data!r})"

    def __len__(self):           # len(buffer)
        return len(self._data)

    def __getitem__(self, i):    # buffer[0]
        return self._data[i]
```

| 魔术方法 | 触发场景 | 用途 |
|---|---|---|
| `__init__(self, ...)` | `obj = Class(...)` | 初始化对象属性 |
| `__str__(self)` | `print(obj)` / `str(obj)` | 用户友好的显示 |
| `__repr__(self)` | 终端直接输入变量名 / `repr(obj)` | 开发者调试用的显示 |
| `__len__(self)` | `len(obj)` | 返回长度 |
| `__getitem__(self, i)` | `obj[i]` | 支持索引访问 |

### 属性封装：@property

`@property` 装饰器将方法伪装成属性，让外部像访问普通属性一样调用方法。内部可以加入读取校验、赋值校验或设为只读。

| 装饰器 | 触发场景 | 说明 |
|---|---|---|
| `@property` | `obj.value`（读取） | 定义 getter，将方法变成可读属性 |
| `@value.setter` | `obj.value = 10`（赋值） | 定义 setter，可加入校验逻辑 |
| `@value.deleter` | `del obj.value`（删除） | 定义 deleter，控制删除行为 |

```python
class SensorReading:
    def __init__(self, value):
        self._value = value      # 下划线开头表示"内部"变量

    @property
    def value(self):              # getter：读取 obj.value
        return self._value

    @value.setter
    def value(self, v):           # setter：赋值 obj.value = 100
        if v < 0:
            raise ValueError("传感器值不能为负")
        self._value = v

    @value.deleter
    def value(self):              # deleter：del obj.value
        raise AttributeError("不允许删除传感器值")

    @property
    def squared(self):            # 只读属性（只有 @property，无 setter）
        return self._value ** 2

s = SensorReading(5)
print(s.value)       # 5         → 走 @property
s.value = 10         #          → 走 @value.setter
s.value = -1         # ValueError
print(s.squared)     # 25        → 只读属性，s.squared = 100 会报错
```

### `_value` 与 `__value`

Python 没有真正的 private，变量可见性靠命名约定：

| 写法 | 含义 | 实际效果 |
|---|---|---|
| `self._value` | 约定"内部变量，别碰" | Python 不做任何处理，纯靠自觉 |
| `self.__value` | 防止子类同名变量冲突 | 定义时自动改名为 `_类名__value` |

```python
class Parent:
    def __init__(self):
        self.__value = 100    # 实际存储为 _Parent__value

class Child(Parent):
    def __init__(self):
        self.__value = 200    # 实际存储为 _Child__value，不会覆盖父类

c = Child()
c._Parent__value    # 100      父类的还在
c._Child__value     # 200      子类自己的
```

> 科研代码中 `_value` 最常用；`__value` 需要区分不同类时才使用。

## @dataclass

`@dataclass`（Python 3.7+）自动为数据容器类生成 `__init__`、`__repr__`、`__eq__` 等样板方法，省去手写。

```python
from dataclasses import dataclass, field

@dataclass
class TrainConfig:
    model_name: str
    lr: float = 0.001
    batch_size: int = 32
    epochs: int = 100
    metrics: list = field(default_factory=list)   # 可变默认值必须用这个
```

### 不使用 vs 使用 @dataclass

超参数散在类的 `__init__` 里，每次加一个参数要改多个地方：

```python
# 不用 dataclass：参数散在 __init__ 里
class NeuralNetwork:
    def __init__(self, lr=0.001, batch_size=32, epochs=100, weight_decay=0.01):
        self.lr = lr
        self.batch_size = batch_size
        self.epochs = epochs
        self.weight_decay = weight_decay
```

用 `@dataclass` 把参数打包成一个"参数包"，通过组合传入：

```python
# 用 dataclass：参数集中管理
class NeuralNetwork:
    def __init__(self, config: TrainConfig):
        self.config = config   # config.lr、config.epochs 统一入口
```

加新参数只需在 `TrainConfig` 加一行，`NeuralNetwork` 不用动。

> 经验法则：类的代码里如果是一堆 `self.xxx = xxx`（存数据）而不是 `def do_something()`（做事情），就该用 `@dataclass`。

## 继承与组合

**继承**：is-a（是一种），子类自动获得父类的一切。**组合**：has-a（拥有），一个类把另一个类的实例当作属性。

```python
# 继承：Dog is an Animal（自动获得 eat 方法）
class Animal:
    def eat(self):
        return "吃东西"

class Dog(Animal):
    def bark(self):
        return "汪汪"

dog = Dog()
dog.eat()   # "吃东西" —— 继承来的，没写一行代码

# 组合：Processor has a Sensor and a Filter
class Sensor:
    def read(self):
        return 42

class Filter:
    def process(self, data):
        return data * 0.9

class Processor:
    def __init__(self):
        self.sensor = Sensor()    # 拥有
        self.filter = Filter()    # 拥有

    def run(self):
        raw = self.sensor.read()
        return self.filter.process(raw)
```

| | 继承 | 组合 |
|---|---|---|
| 关系 | is-a（是一种） | has-a（拥有） |
| 代码复用 | 直接拿父类方法用 | 调用组件的方法 |
| 灵活性 | 继承链定下难改 | 可运行时替换组件 |
| 典型场景 | `Dog → Animal` | `Processor` 拥有 `Sensor` + `Filter` |

> 优先使用组合而非继承。能说"X 拥有 Y"就用组合，能确信"X 是一种 Y"才用继承。

# 概念 3：模块化与代码重构

## 拆分原则

把一个大文件拆成多个小模块，每个模块只做一件事：

- **功能单一**：`config.py` 只管配置，`data_loader.py` 只管读数据
- **模块间通过 import 调用**，不复制粘贴代码

```
project/
  ├── src/
  │   ├── __init__.py
  │   ├── config.py          # 超参数、路径配置
  │   ├── data_loader.py     # 数据读取与预处理
  │   ├── model.py           # 模型定义
  │   └── train.py           # 训练循环
  └── notebooks/
      └── experiment.ipynb   # 实验脚本，调用 src 里的模块
```

## `__init__.py` 的作用

`__init__.py` 标记文件夹为 Python 包，有了它才能 `import` 该目录里的模块。

```
my_project/
  ├── utils/
  │   ├── __init__.py          ← 有这个，utils 才是"包"
  │   ├── math_utils.py
  │   └── io_utils.py
  └── main.py
```

```python
# main.py —— 可以导入，因为 utils/ 下有 __init__.py
from utils.math_utils import add
from utils.io_utils import read_csv
```

没有 `__init__.py`，`from utils.xxx import ...` 会报错。

## 绝对导入与相对导入

```python
# 假设目录结构如上，在 utils/io_utils.py 中导入 math_utils

# 绝对导入：从项目根写全路径，一眼知道在哪
from utils.math_utils import add

# 相对导入：用 . 表示位置关系，当前包内
from .math_utils import add
```

| 符号 | 含义 |
|---|---|
| `.` | 当前包所在目录 |
| `..` | 上级包 |

| | 绝对导入 | 相对导入 |
|---|---|---|
| 路径写法 | `from utils.xxx import ...` | `from .xxx import ...` |
| 可读性 | 一眼知道模块在哪 | 需脑补位置关系 |
| 适用场景 | 项目内各模块之间 | `__init__.py` 汇总导出 |

> 科研建议：项目内部模块之间用绝对导入更直观；相对导入主要在 `__init__.py` 里汇总时用。

## 配置文件格式对比

| | YAML | JSON | TOML | .env |
|---|---|---|---|---|
| 后缀 | `.yaml`/`.yml` | `.json` | `.toml` | `.env` |
| 语法 | 缩进表示层级 | 花括号 + 引号 | `[section]` + `key = value` | `KEY=VALUE` |
| 支持注释 | ✅ `# 注释` | ❌ 不支持 | ✅ `# 注释` | ✅ `# 注释` |
| 可读性 | 最好，无多余符号 | 层级深时视觉噪音大 | 好，接近 INI 风格 | 每一行独立，简单 |
| Python 读取 | `pip install pyyaml` | 内置 `import json` | `pip install toml` | `pip install python-dotenv` |
| 科研常用场景 | 超参数配置 | 数据交换 | `pyproject.toml` 项目元数据 | 密钥、密码等敏感信息 |

> 科研中 YAML（超参数）和 TOML（项目配置）最常用；`.env` 用于存密码等不该提交 git 的敏感信息。

## argparse 命令行参数

`argparse`（Python 标准库）让你不用改代码就能从命令行传入参数，跑实验时快速切换配置。

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--lr", type=float, default=0.001, help="学习率")
parser.add_argument("--epochs", type=int, default=100, help="训练轮数")
parser.add_argument("--verbose", action="store_true", help="详细输出")
args = parser.parse_args()

print(f"lr={args.lr}, epochs={args.epochs}")
```

| 参数写法 | 效果 |
|---|---|
| `default=` | 不传时的默认值 |
| `type=` | 自动转换类型（`int`/`float`/`str`） |
| `help=` | `python train.py --help` 时的说明文字 |
| `action="store_true"` | 布尔开关，传了就变 `True`，不传是 `False` |

### config.yaml + argparse 配合使用

| | config.yaml | argparse |
|---|---|---|
| 作用 | 存长期默认配置 | 临时覆盖参数 |
| 修改方式 | 编辑 YAML 文件 | 命令行传参 |
| Python 读取 | `yaml.safe_load(open("config.yaml"))` | `parser.parse_args()` |
| 分工 | 默认值来源 | 跑实验时的临时改动 |

```yaml
# config.yaml
lr: 0.001
epochs: 100
```

```python
import yaml, argparse

with open("config.yaml") as f:
    config = yaml.safe_load(f)

parser = argparse.ArgumentParser()
parser.add_argument("--lr", type=float, default=config["lr"])      # 默认值来自 YAML
parser.add_argument("--epochs", type=int, default=config["epochs"])
args = parser.parse_args()
# 命令行传了就用命令行的，没传就用 YAML 默认值
```

```bash
python train.py                    # 用 YAML 默认值
python train.py --lr 0.01          # 覆盖 lr，其他默认
python train.py --lr 0.1 --epochs 200  # 全部覆盖
```

> YAML 存"通常不改的默认值"，argparse 做"今天想换的参数"。跑完确认后需要长期保留的改回 YAML。

## loguru 日志库

`loguru` 是第三方日志库（`pip install loguru`），替代 `print()` 和标准库 `logging`，开箱即用。

### 核心用法

| 操作 | 代码 | 说明 |
|---|---|---|
| 导入 | `from loguru import logger` | 无需创建实例，直接使用全局 `logger` |
| INFO | `logger.info("加载完成")` | 常规信息 |
| DEBUG | `logger.debug(f"shape={data.shape}")` | 调试信息 |
| WARNING | `logger.warning("可能精度丢失")` | 警告 |
| ERROR | `logger.error(f"文件 {path} 不存在")` | 错误 |
| 写入文件 | `logger.add("app.log")` | 一行代码同时输出到文件和控制台 |
| 文件轮转 | `logger.add("app.log", rotation="10 MB")` | 超过 10MB 自动切分 |
| 时间轮转 | `logger.add("app.log", rotation="00:00")` | 每天午夜切分 |
| 保留天数 | `logger.add("app.log", retention="7 days")` | 只保留最近 7 天 |
| 捕获异常 | `@logger.catch` | 装饰器，自动记录函数内未捕获的异常 |
