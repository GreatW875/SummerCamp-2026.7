# 运动识别系统 —— 数据处理流水线说明

> 本文档从宏观视角介绍本系统中数据处理部分的整体架构、各阶段的职责划分及所使用的方法/算法。

---

## 一、整体架构总览

本系统的数据处理流程分为 **离线训练流水线** 和 **在线推理流水线** 两条路径，二者共享同一套预处理和特征提取代码，保证训练与推理的一致性。

```
┌──────────────────────────────────────────────────────────────────┐
│                    离线训练流水线                                  │
│                                                                  │
│  公开数据集 / 合成数据  ──→  预处理  ──→  滑窗分段  ──→               │
│                            特征提取  ──→  模型训练  ──→  模型文件    │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│                    在线推理流水线                                  │
│                                                                  │
│  手机传感器  ──WebSocket──→  接收校验  ──→  环形缓冲  ──→            │
│                            推理触发  ──→  特征提取  ──→            │
│                            模型预测  ──→  去抖动  ──→  结果推送     │
└──────────────────────────────────────────────────────────────────┘
```

从宏观上看，整个数据处理流程可划分为以下 **7 个阶段**：

| 编号 | 阶段 | 执行位置 | 模式 |
|------|------|----------|------|
| 1 | 数据采集 | 手机端浏览器 | 在线 |
| 2 | 数据接收与校验 | 服务端 | 在线 |
| 3 | 信号预处理 | 服务端 + 训练脚本 | 在线 & 离线 |
| 4 | 特征提取 | 服务端 + 训练脚本 | 在线 & 离线 |
| 5 | 模型训练 | 训练脚本 | 离线 |
| 6 | 推理与后处理 | 服务端 | 在线 |
| 7 | 结果输出与持久化 | 服务端 + 前端 | 在线 |

## 二、阶段 1：数据采集

**执行位置：** 手机端浏览器  
**核心文件：** `src/frontend/static/js/collector.js`

### 数据来源

通过 HTML5 **DeviceMotion API** 和 **Geolocation API** 从智能手机内置传感器实时采集数据。

| 传感器 | 数据维度 | 采样率 |
|--------|----------|--------|
| 加速度计（含重力） | `acc_x`, `acc_y`, `acc_z`（m/s²） | 50 Hz |
| 陀螺仪 | `gyro_x`, `gyro_y`, `gyro_z`（deg/s） | 50 Hz |
| GPS | `lat`, `lng` | 1 Hz |

### 前端缓冲策略

- 手机端每收到一条传感器数据，先存入 JS 本地队列（容量 100 条）
- 队列满后，每 **200ms** 批量打包发送一次，减少 WebSocket 消息频率，降低带宽压力

### 每帧数据格式

```json
{
  "session_id": 1,
  "timestamp": 1711564800.123,
  "acc_x": 0.15, "acc_y": 9.81, "acc_z": 0.23,
  "gyro_x": 0.01, "gyro_y": -0.02, "gyro_z": 0.05,
  "lat": 39.9042, "lng": 116.4074
}
```

## 三、阶段 2：数据接收与校验

**执行位置：** Python 服务端  
**核心文件：** `src/api/socket_handlers.py`, `src/service/collector.py`

### WebSocket 房间隔离

服务端使用 **Socket.IO + gevent**，按客户端类型自动分配房间：
- 手机端 → `mobile` 房间
- 电脑 Dashboard → `dashboard` 房间
- 两房间消息隔离，互不干扰

### 数据校验 (`_validate()`)

每条传感器数据入库/入缓冲前执行以下检查：

| 校验项 | 规则 |
|--------|------|
| NaN/Inf 检测 | 所有数值字段不能为 NaN 或 无穷 |
| 类型检查 | 所有传感器字段必须为数值类型 |
| 范围检查 | 加速度 [-40, 40] m/s²，角速度 [-2000, 2000] deg/s |
| GPS 范围 | 纬度 [-90, 90]，经度 [-180, 180] |

校验不通过的数据直接丢弃，不计入缓冲区。

### 环形缓冲区

使用 Python `collections.deque`（最大容量 300 条 = 3 × 2s窗口 × 50Hz）作为环形缓冲区：
- 新数据从右侧加入
- 缓冲区满后最旧数据自动丢弃
- 每次推理时取最近 100 条（恰好一个 2 秒窗口）

## 四、阶段 3：信号预处理

**执行位置：** Python 服务端（推理时）+ 训练脚本（训练时）  
**核心文件：** `src/core/preprocess.py`  
**配置文件：** `configs/model/preprocess.yaml`

预处理阶段包含 **4 个子步骤**，按顺序执行：

### 4.1 巴特沃斯低通滤波

| 属性 | 说明 |
|------|------|
| 方法 | 4 阶巴特沃斯 IIR 低通滤波器 |
| 截止频率 | 20 Hz |
| 采样率 | 50 Hz |
| 实现 | `scipy.signal.butter()` 计算系数 + `scipy.signal.filtfilt()` 双向零相位滤波 |
| 目的 | 滤除高频噪声，IMU 有效运动信号通常低于 20 Hz |

> `filtfilt` 的双向滤波特性保证了滤波后信号**无相位偏移**，对后续时序分析至关重要。

### 4.2 重力分离（可选）

| 属性 | 说明 |
|------|------|
| 方法 | 一阶 IIR 高通滤波器 |
| 公式 | `gravity[i] = α · gravity[i-1] + (1-α) · acc[i]`，`linear[i] = acc[i] - gravity[i]` |
| 平滑系数 | α = 0.8 |
| 默认状态 | **关闭**（保留重力信息更有利于区分静态/走路/跑步） |

### 4.3 移动平均平滑

| 属性 | 说明 |
|------|------|
| 方法 | 滑动窗口卷积 |
| 窗口大小 | 5 个样本（0.1 秒） |
| 实现 | `numpy.convolve()`，核函数 = `[1/5, 1/5, 1/5, 1/5, 1/5]` |
| 目的 | 消除瞬时毛刺，让信号更平滑 |

### 4.4 Z-score 标准化

| 属性 | 说明 |
|------|------|
| 方法 | Z-score 归一化 |
| 公式 | `x' = (x - μ) / σ` |
| 范围 | 每个传感器通道独立计算 |
| 防零保护 | σ < 1e-10 时设为 1.0 |

### 4.5 滑动窗口分段

| 属性 | 说明 |
|------|------|
| 窗口大小 | 100 个样本 = **2 秒**（@ 50 Hz） |
| 步长 | 50 个样本 = **1 秒**（@ 50 Hz） |
| 重叠率 | **50%** |
| 不足处理 | 数据不足一个窗口时用零填充首部 |

> 50% 重叠率确保运动状态变化时不会遗漏过渡帧，同时每个窗口内包含足够的信息供特征提取。

## 五、阶段 4：特征提取

**执行位置：** Python 服务端 + 训练脚本（共用代码，唯一真源）  
**核心文件：** `src/core/features.py`  
**配置文件：** `configs/model/features.yaml`

这是整个流水线的核心环节。每个 2 秒窗口（100 样本 × 6 通道）经过特征提取后，被压缩为一个 **112 维特征向量**。特征分为三大类：

### 5.1 时域特征（60 维）

对 **6 个通道**（acc_x, acc_y, acc_z, gyro_x, gyro_y, gyro_z）各自提取 **10 个特征**：

| 特征 | 含义 | 物理意义 |
|------|------|----------|
| `mean` | 均值 | 信号基线偏移 |
| `variance` | 方差 | 运动剧烈程度 |
| `std` | 标准差 | 同上 |
| `min` | 最小值 | 运动幅度下限 |
| `max` | 最大值 | 运动幅度上限 |
| `range` | 极差（max - min） | 运动幅度 |
| `rms` | 均方根 | 信号有效能量 |
| `sma` | 信号幅度面积（Σ\|x\|/N） | 整体活动量 |
| `iqr` | 四分位距（Q3 - Q1） | 信号分布的稳健散布度 |
| `zero_crossing_rate` | 过零率 | 信号振荡频率的时域近似 |

### 5.2 频域特征（48 维）

对 **6 个通道**各自做 **FFT（快速傅里叶变换）**，每通道提取 **8 个特征**：

| 特征 | 含义 |
|------|------|
| `dominant_frequency` | 主频 —— 频谱幅度最大的频率 |
| `spectral_energy` | 总谱能量 —— Σ\|FFT\|² |
| `spectral_entropy` | 谱熵 —— 频谱分布的无序程度（越高越分散） |
| `mean_frequency` | 加权平均频率 |
| `band_0_energy_ratio` | [0.5, 3.0] Hz 频带能量占比 —— 走路频率 |
| `band_1_energy_ratio` | [3.0, 6.0] Hz 频带能量占比 —— 跑步频率 |
| `band_2_energy_ratio` | [6.0, 15.0] Hz 频带能量占比 —— 高频 |

> 频带能量比是非常关键的区分特征——不同运动的周期性频率落在不同频段。

### 5.3 组合特征（4 维）

跨越 x/y/z 三个轴计算合成量，不区分方向：

| 特征 | 公式 |
|------|------|
| `acc_magnitude_mean` | mean(√(acc_x² + acc_y² + acc_z²)) |
| `acc_magnitude_std` | std(√(acc_x² + acc_y² + acc_z²)) |
| `gyro_magnitude_mean` | mean(√(gyro_x² + gyro_y² + gyro_z²)) |
| `gyro_magnitude_std` | std(√(gyro_x² + gyro_y² + gyro_z²)) |

**特征维度汇总：**

| 类别 | 维度数 |
|------|--------|
| 时域特征（6通道 × 10特征） | 60 |
| 频域特征（6通道 × 8特征） | 48 |
| 组合特征 | 4 |
| **合计** | **112** |

## 六、阶段 5：模型训练（离线）

**执行位置：** 训练脚本  
**核心文件：** `ml/train.py`, `ml/dataset.py`

### 6.1 训练数据

| 来源 | 说明 |
|------|------|
| UCI HAR 公开数据集 | 30 位被试，6 种活动，50 Hz，加速度 + 陀螺仪 |
| MotionSense 公开数据集 | 补充 running 类别 |
| 合成数据 | 基于物理模型（正弦波 + 高斯噪声）生成，增强数据量 |
| 混合数据集 | 以上来源按策略组合 |

**分类标签（3 类）：** `static`, `walking`, `running`

### 6.2 数据集构建流程

```
原始数据 (CSV)
   │
   ├── preprocess_pipeline()  →  巴特沃斯滤波 + 平滑 + 标准化
   ├── sliding_window()       →  2秒窗口, 50% 重叠
   ├── 窗口标签 (众数投票)
   ├── extract_features()     →  112维向量
   └── train_test_split()     →  80% 训练 / 20% 测试（分层抽样）
```

### 6.3 分类模型

#### 主模型：随机森林（Random Forest）

| 超参数 | 值 | 说明 |
|--------|-----|------|
| `n_estimators` | 100 | 决策树数量 |
| `max_depth` | 15 | 树最大深度，防止过拟合 |
| `min_samples_split` | 5 | 节点分裂最少样本数 |
| `min_samples_leaf` | 2 | 叶节点最少样本数 |
| `class_weight` | `balanced` | 自动平衡类别权重 |

**选择理由：**
- 对特征量纲不敏感，无需额外归一化
- 天然输出概率（`predict_proba`），方便置信度展示
- 可解释性强（特征重要性排序）
- 不易过拟合，适合中小规模数据集

#### 备选模型：支持向量机（SVM）

| 超参数 | 值 | 说明 |
|--------|-----|------|
| `kernel` | `rbf` | 径向基核函数 |
| `C` | 1.0 | 正则化系数 |
| `gamma` | `scale` | 核函数带宽 |
| `probability` | `True` | 启用概率输出 |

### 6.4 模型保存

训练完成后以 Pickle 格式保存，包含完整元信息：

```python
{
    "model": trained_model,
    "labels": ["static", "walking", "running"],
    "feature_dim": 112,
    "model_type": "RandomForestClassifier",
    "metrics": {  # 准确率、精确率、召回率、F1 等
        "accuracy": 0.92,
        ...
    }
}
```

保存为两个副本：带时间戳的历史版本 + `gait_classifier.pkl`（当前使用）。

## 七、阶段 6：推理与后处理（在线）

**执行位置：** Python 服务端  
**核心文件：** `src/service/inference.py`

### 7.1 推理触发机制

- **触发频率：** 每 **1.0 秒** 一次
- **前置条件：** 环形缓冲区至少包含 50 条数据（半窗口），确保有足够的信号
- **窗口提取：** 取缓冲区最近 100 条数据 → 拆分为 `acc`（100×3）和 `gyro`（100×3）两个矩阵

### 7.2 推理步骤

```
recent 100 samples
   │
   ├── extract_feature_vector(acc_window, gyro_window)
   │     └── 时域 60 维 + 频域 48 维 + 组合 4 维 = 112 维
   │
   ├── 维度对齐 (截断或零填充，确保与训练时一致)
   │
   ├── model.predict(features)  → 类别标签
   │
   ├── 置信度计算：
   │     RandomForest: predict_proba() 直接输出概率
   │     SVM: softmax(decision_function()) 归一化
   │
   └── 去抖动投票 (_debounce)
```

### 7.3 去抖动机制

| 属性 | 说明 |
|------|------|
| 方法 | 多数投票（Majority Voting） |
| 窗口大小 | 最近 **3 次** 推理结果 |
| 实现 | `collections.Counter` 取 `most_common(1)` |
| 目的 | 防止单帧误判导致结果显示跳变，提升输出稳定性 |

## 八、阶段 7：结果输出与持久化

### 8.1 WebSocket 实时推送

| 事件名 | 目标房间 | 内容 |
|--------|----------|------|
| `dashboard:sensor_stream` | Dashboard | 原始传感器波形数据（供 ECharts 实时绘图） |
| `dashboard:inference_result` | Dashboard + Mobile | 分类结果（标签、置信度、各类概率） |
| `dashboard:gait_params` | Dashboard | 步态参数（步频、速度、距离） |

### 8.2 SQLite 持久化

使用 **SQLite WAL 模式** 持久化 3 类数据：

| 表 | 存储内容 |
|----|----------|
| `sessions` | 运动会话元信息（标签、起止时间、时长、状态） |
| `sensor_data` | 原始传感器记录（时间戳、加速度、角速度、GPS） |
| `inference_results` | 推理结果（预测标签、置信度、特征快照、是否人工纠正） |

写入采用批量策略（每 50 条或每 2 秒一次），减少磁盘 I/O 开销。

### 8.3 前端可视化

| 可视化组件 | 所用技术 | 展示内容 |
|-----------|----------|----------|
| 实时波形图 | ECharts 折线图 | 加速度/角速度三通道 + 合成量，最近 500 点 |
| GPS 轨迹地图 | Leaflet | 运动路线实时打点 |
| 分类结果卡片 | HTML + CSS 进度条 | 当前运动类型、置信度、各类概率条 |
| 纠正按钮 | HTML Button | 允许用户手工修正分类结果 |
