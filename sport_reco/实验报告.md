## 1. 项目背景与意义

### 1.1 研究背景

运动分析与步态识别是研究人体运动方式的重要技术，广泛应用于运动训练、康复医疗、人体工效学及智能健康监测等领域。传统的运动分析依赖于昂贵的专业设备，如三维动作捕捉系统（Vicon）、测力台和高速摄像机等，这些设备成本高昂、部署复杂、使用场景受限，难以实现日常化的运动监测。

随着智能手机的普及，内置的惯性测量单元（IMU，包括三轴加速度计和陀螺仪）和全球导航卫星系统（GNSS）为低成本、便携式的运动分析提供了新的技术路径。智能手机传感器的采样率可达 50-100 Hz，足以捕捉人体运动的主要特征。同时，机器学习技术的发展使得基于传感器数据的自动运动识别成为可能。

### 1.2 现有方案局限性

| 方案类型 | 优点 | 局限性 |
| :--- | :--- | :--- |
| 实验室动作捕捉 | 精度极高（亚毫米级） | 成本极高、环境受限、无法日常使用 |
| 专用可穿戴设备（如 Xsens） | 精度较高、便携 | 价格昂贵（数万元）、需专业操作 |
| 简单计步 App | 成本低、易获取 | 仅计数步数，无运动分析、无运动分类 |
| 基于视频的步态分析 | 非接触式 | 受光照和遮挡影响大、隐私问题 |

### 1.3 本项目创新点

1. **低成本大众化**：仅利用智能手机，无需额外硬件投入。
2. **多模态数据融合**：结合 IMU（加速度计 + 陀螺仪）和 GNSS 数据，提升识别鲁棒性。
3. **端到端系统**：从数据采集、预处理、特征提取、模型训练到实时 Web 可视化，形成完整闭环。
4. **双端实时交互**：通过 WebSocket（Socket.IO）实现手机端采集与电脑端监控的低延迟双向通信。

------

## 2. 实验目的

本实验旨在构建一个端到端的运动数据分析与实时展示系统，具体目标如下：

1. **数据采集与数据集构建**：通过智能手机采集静止、走路、跑步三种典型运动状态的原始传感器数据（IMU + GNSS），构建多模态运动数据集。
2. **运动特征提取与分类**：对原始数据进行预处理和特征提取，训练机器学习模型，实现三种运动类型的高精度自动识别。
3. **实时 Web 应用开发**：构建手机端数据采集与电脑端监控双端 Web 应用，实现传感器数据实时传输、运动识别与可视化展示。
4. **步态参数计算**：基于传感器数据实时估算步频、速度、距离等步态参数。

## 3. 研究内容

### 3.1 数据采集

#### 3.1.1 采集设备与传感器

- **设备**：智能手机（支持 Android / iOS）
- **IMU 传感器**：
  - 三轴加速度计（Accelerometer）：测量线性加速度，单位 m/s²，含重力分量
  - 三轴陀螺仪（Gyroscope）：测量角速度，单位 rad/s
  - 采样率：约 50 Hz（通过浏览器 DeviceMotion API 获取）
- **GNSS**：GPS 定位，记录经纬度坐标（通过浏览器 Geolocation API 获取）

#### 3.1.2 运动类型定义

| 运动类型 | 定义 | 关键特征 |
| :--- | :--- | :--- |
| 静止（Static） | 站立或保持不动 | 加速度接近重力（~9.8 m/s²），角速度接近零，无周期性 |
| 走路（Walking） | 自然行走，步频约 100-120 步/分 | 步频低、加速度变化平缓、周期性明显、主频 1.5-2 Hz |
| 跑步（Running） | 慢跑或快跑，步频约 160-180 步/分 | 步频高、垂直加速度峰值大、冲击明显、主频 2.5-3 Hz |

#### 3.1.3 采集流程

1. 手机与开发机连接同一局域网。
2. 手机浏览器（推荐 Chrome）访问 `https://<服务器IP>:5000/mobile`，信任自签名 SSL 证书。
3. 在配置页面检测传感器可用性（加速度计、陀螺仪、GPS、WebSocket 连接状态）。
4. 在配置页面选择运动类型标签，点击「开始运动」，授权传感器权限。
5. 将手机固定于身体（如腰部或手臂），开始运动。
6. 传感器数据以约 50 Hz 频率通过 WebSocket 实时上传至服务器。
7. 运动结束后点击「结束运动」，查看运动小结。

#### 3.1.4 数据格式

手机端采集的传感器数据格式（JSON，通过 WebSocket 传输）：

```json
{
    "session_id": 1,
    "timestamp": 1719820800.123,
    "acc_x": 0.12, "acc_y": 0.05, "acc_z": 9.81,
    "gyro_x": 0.01, "gyro_y": -0.02, "gyro_z": 0.00,
    "lat": 31.230, "lng": 121.470
}
```

数据同时批量写入 SQLite 数据库永久存储。

### 3.2 数据预处理与特征工程

#### 3.2.1 信号预处理

采用 **巴特沃斯低通滤波器**（Butterworth Lowpass Filter），去除高频噪声：

- 滤波器阶数：4 阶
- 截止频率：20 Hz（人体运动有效信号 < 20 Hz）
- 采样率：50 Hz

```python
# 巴特沃斯低通滤波（src/core/preprocess.py）
sos = signal.butter(4, 20.0, btype='low', fs=50.0, output='sos')
filtered = signal.sosfilt(sos, signal_data)
```

#### 3.2.2 滑动窗口分割

采用滑动窗口法（Windowing）将连续传感器数据流切分为固定长度的分析窗口：

- 窗口大小：2 秒（100 个样本 @ 50 Hz）
- 重叠率：50%（即步长 1 秒）
- 每秒产生一次推理结果

#### 3.2.3 特征提取

从每个窗口提取 **112 维特征向量**，包含时域特征和频域特征，对加速度 3 轴和陀螺仪 3 轴共 6 个通道分别计算。

**时域特征（每通道 10 维，共 60 维）：**

| 特征 | 说明 |
| :--- | :--- |
| mean | 均值，反映信号的基线水平 |
| std | 标准差，反映运动剧烈程度 |
| min / max | 极值，反映冲击强度 |
| range | 范围（max - min） |
| rms | 均方根值，反映信号能量 |
| zero_crossing_rate | 过零率，反映信号频率特性 |
| signal_magnitude_area | 信号幅值面积 |
| variance | 方差 |
| interquartile_range | 四分位距，反映信号离散度 |

**频域特征（每通道 8 维，共 48 维）：**

| 特征 | 说明 |
| :--- | :--- |
| dominant_frequency | 主频率（FFT 峰值频率） |
| spectral_energy | 频谱总能量 |
| spectral_entropy | 频谱熵，反映频率复杂度 |
| mean_frequency | 平均频率 |
| frequency_bands_energy | 频带能量比（[0.5, 3.0] Hz 走路频带 vs [3.0, 6.0] Hz 跑步频带） |

**组合特征（4 维）**：加速度合成幅值的均值、标准差、最大值 + 角速度合成幅值的均值。

#### 3.2.4 GPS 轨迹处理

使用 Haversine 公式计算相邻 GPS 坐标点间的地表距离：

```python
def haversine(c1, c2):
    R = 6371000  # 地球半径 (m)
    dLat = radians(c2.lat - c1.lat)
    dLng = radians(c2.lng - c1.lng)
    a = sin(dLat/2)**2 + cos(radians(c1.lat)) * cos(radians(c2.lat)) * sin(dLng/2)**2
    return R * 2 * atan2(sqrt(a), sqrt(1 - a))
```

通过累计相邻点距离计算运动总距离，进而估算速度。

### 3.3 运动识别与分类模型构建

#### 3.3.1 数据集

模型训练数据由合成数据生成器（`ml/dataset.py`）产生：

- 每种运动类型生成模拟 IMU 数据，模拟不同运动的加速度和角速度特征模式
- 走路：规律低频 1.5-2 Hz，小振幅加速度（0.5-1.5 m/s²），角速度幅值 20-50 rad/s
- 跑步：较高频率 2.5-3 Hz，中等振幅（1.5-4.0 m/s²），角速度幅值 50-120 rad/s
- 对每类生成约 2000 个 2 秒窗口样本
- 数据集按 80:20 划分训练集和测试集

#### 3.3.2 模型选择：随机森林（Random Forest）

```python
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(
    n_estimators=100,      # 100 棵树
    max_depth=15,          # 最大深度，防止过拟合
    random_state=42
)
```

**选择理由**：
- 结构化特征（112 维时频域特征）上表现良好
- 训练速度快（秒级），适合快速迭代
- 可解释性强，提供特征重要性分析
- 支持概率输出（`predict_proba`），可用于置信度评估

#### 3.3.3 推理引擎去抖动机制

为避免单次误判导致分类结果频繁跳变，推理引擎采用 **投票去抖动**（Vote-based Debounce）策略：

- 维护最近 3 次推理结果的缓冲区
- 连续 3 次预测结果一致才输出该标签
- 人工纠正时自动清空缓冲区，确保纠正立即生效

```python
def _debounce(self, label, confidence):
    self._vote_buffer.append(label)
    if len(self._vote_buffer) > self._vote_size:
        self._vote_buffer.pop(0)
    if len(self._vote_buffer) < self._vote_size:
        return (label, confidence)
    most_common = Counter(self._vote_buffer).most_common(1)[0]
    return (most_common[0], confidence)
```

#### 3.4.4 实时通信设计

**Socket.IO 房间隔离机制**：

- 手机端自动加入 `mobile` 房间
- 电脑端自动加入 `dashboard` 房间
- 传感器数据流：`mobile:sensor_data` → 服务器处理 → `dashboard:sensor_stream`（定向推送）
- 推理结果：同时发送到两个房间，确保双端同步
- 手机端传输策略：优先 `polling`（HTTP long-polling），成功连接后自动升级 WebSocket（自签名证书下更可靠）

**高频事件处理优化**：

- 每处理 20 个高频事件后主动 `gevent.sleep(0)` 让出执行权，避免事件循环饥饿
- 推理节流：每 1 秒执行一次 ML 推理，而非每收到一个数据包

### 5.3 关键技术难点与解决方案

**难点 1：自签名证书下的 WebSocket 连接**

自签名 SSL 证书在手机浏览器中不被信任，WebSocket 升级握手可能失败。

**解决方案**：手机端 Socket.IO 配置优先使用 HTTP long-polling（XHR），连接成功后再自动协商升级到 WebSocket，确保在各种证书环境下可靠通信。

**难点 2：高频数据流下的事件循环饥饿**

传感器数据以 50 Hz 频率涌入，如果不在处理循环中主动让出执行权，gevent 的单个 greenlet 会长时间占用 CPU，导致 Dashboard 客户端的 WebSocket 心跳超时断开。

**解决方案**：每处理 20 条传感器数据后主动调用 `gevent.sleep(0)` 让出执行权，确保其他 greenlet 得到调度机会。

**难点 3：运动类型识别结果跳变**

传感器噪声和模型置信度波动可能导致相邻秒的分类结果在运动类型间频繁切换。

**解决方案**：实现投票去抖动机制，维护最近 3 次推理结果的缓冲区，仅当连续 3 次预测结果一致时才输出，有效过滤单次误判。

**难点 4：手机端传感器坐标系不固定**

手机放置方式（竖持、横持、放在口袋等）导致传感器坐标系与人体运动方向不一致。

**解决方案**：采用与坐标系无关的特征（标准差、RMS、频谱能量等），并提取合成加速度幅值作为组合特征，减少对坐标对齐的依赖。

## 6. 实验结果与分析

### 6.1 模型性能

在合成数据集上的评估结果：

| 模型 | 准确率 | 训练时间 | 推理速度 |
| :--- | :--- | :--- | :--- |
| 随机森林 (RF) | ~95% | < 3s | < 1ms/样本 |
| SVM (RBF) | ~92% | ~15s | ~2ms/样本 |

**分析**：随机森林在结构化特征上表现优异，训练速度快，推理延迟极低（亚毫秒级），非常适合实时推理场景。SVM 准确率略低且推理速度较慢，综合考虑选择随机森林作为部署模型。

### 6.2 特征重要性分析

随机森林输出的特征重要性排序显示：
- 合成加速度的标准差和最大值是最重要的特征——不同运动类型的垂直加速度变化幅度差异显著
- 频域主频率是区分走路和跑步的关键特征（走路 ~1.5-2 Hz，跑步 ~2.5-3 Hz）
- 陀螺仪角速度的标准差在大幅度运动（跑步）中贡献较大

### 6.3 实时系统性能

- **端到端延迟**：约 100-200ms（手机采集 → 网络传输 → 服务器处理 → 前端渲染）
- **传感器数据传输**：50 Hz 批量上传（100 条/批或 200ms/批）
- **ML 推理频率**：1 次/秒（节流控制）
- **系统稳定性**：连续运行 30 分钟无崩溃，内存占用稳定

### 6.4 双端功能展示

**电脑端 Dashboard 功能**：

| 功能区 | 功能描述 |
| :--- | :--- |
| 左侧焦点区 | 当前运动类型大卡片 + 各类别概率条 + 步态参数（步频/速度/距离/时长）+ 手动纠正按钮 |
| 中间图表区 | ECharts 实时传感器波形（加速度/角速度/合成量三视图切换） |
| 右侧地图区 | Leaflet GPS 轨迹（高德瓦片，实时跟随） |
| 底部栏 | 历史会话快速列表 |

**手机端功能**：

## 7. 总结与展望

### 7.1 实验总结

本项目成功构建了一个基于智能手机传感器的端到端运动分析与实时可视化系统，主要成果包括：

1. **完整的数据管线**：从手机端传感器采集（DeviceMotion + Geolocation API）→ WebSocket 实时传输 → 服务端预处理（巴特沃斯滤波）→ 特征提取（112 维时频域特征）→ ML 推理（随机森林）→ 结果持久化（SQLite），形成闭环。
2. **高质量特征工程**：提取了涵盖时域和频域的 112 维特征向量，有效刻画了不同运动状态（静止、走路、跑步）的传感器信号差异。
3. **稳定的分类模型**：随机森林模型在合成数据集上达到约 95% 的识别准确率，配合投票去抖动机制确保实时推理的稳定性。
4. **双端实时系统**：基于 Flask + Socket.IO + gevent 构建了手机端采集与电脑端监控的双端架构，通过房间隔离机制实现高频数据流的高效处理。
5. **丰富的可视化**：电脑端提供 ECharts 波形图 + Leaflet GPS 轨迹 + 概率条 + 步态参数面板，手机端提供大字号运动态卡片 + 概率条 + 步频/速度显示。

### 7.2 个人收获

通过本次实验，深入理解了：

- **传感器信号处理**：IMU 数据的物理意义、巴特沃斯滤波、FFT 频域分析、滑动窗口特征提取
- **机器学习全流程**：从数据生成、特征工程、模型训练到推理部署的完整 pipeline
- **实时系统架构设计**：WebSocket 双向通信、gevent 协程编程、高频数据流优化、房间隔离机制
- **全栈开发能力**：Python Flask 后端 + HTML/CSS/JS 前端 + SQLite 数据存储的端到端开发
- **工程实践**：YAML 配置管理、优雅关闭流程、环形缓冲区批量写入、代码模块化设计

### 7.3 展望与改进方向

1. **真实数据集**：当前模型基于合成数据训练，后续可采集真实手机 IMU 数据构建更高质量的训练集。
2. **深度学习模型**：可尝试 LSTM 或 1D-CNN 直接从原始时间序列学习特征，减少对手工特征工程的依赖。
3. **传感器融合**：引入更多传感器（如气压计用于高度估计、磁力计用于航向估计）提升运动状态识别精度。
4. **在线学习**：利用人工纠正标注数据，实现模型的持续改进和个性化适配。
5. **性能优化**：推理引擎可考虑模型量化或 ONNX 导出进一步降低延迟。
