# 阶段二：树模型与集成学习

## 一、决策树与 Bagging 集成

### 决策树（Decision Tree,DT）（监督学习）

> 像"二十问"游戏，通过一系列特征阈值问题逐步分类。核心：每个节点找一个特征+阈值，使分完后两边最"纯净"。

**不纯度衡量**：

| 指标 | 公式 | 范围 |
|------|------|------|
| **基尼系数 (Gini)** | $G = 1 - \sum p_k^2$ | 0(纯) ~ 0.5(最乱) |
| **信息熵 (Entropy)** | $H = -\sum p_k \log p_k$ | 0(纯) ~ 1(最乱) |

> 两者效果几乎一样，Gini 不用 log 计算更快，sklearn 默认用 Gini。CART 选使不纯度下降最多的切分点。

**剪枝**：树不限制会长到每叶一个样本（过拟合）。预剪枝（`max_depth`等限制生长）+ 后剪枝（长完后删子树）。

**特点**：可解释性极强、**不需标准化**（按阈值切分，不受量纲影响）、但容易过拟合且不稳定。

### 随机森林（Random Forest,RF）（监督学习）

> **Bagging + 特征随机**：有放回抽样生成 N 份训练集，每份训练一棵树；每次分裂只随机选 √d 个特征。最终投票/取平均。

**Bagging 降方差原理**：

$$\text{Var}_{\text{森林}} = \rho \cdot \sigma^2 + \frac{(1-\rho)}{N} \cdot \sigma^2$$

- 单棵树：低偏差高方差（过拟合）
- 多树平均：方差降为 1/N（树独立时）
- 特征随机：降低树间相关性 ρ（去相关，增强降方差效果）
- 增加树数 N：方差下降但边际递减

> **Bagging 的精髓**：用深树保证低偏差（和单棵树一样），用多树平均降低方差。平均不改变偏差（每棵树都偏同一方向，平均还是偏），只降低"有的偏左有的偏右"的波动（方差）。即**不改善偏差，只降低方差**。

**特点**：不易过拟合、不需标准化、自带 OOB（Out-Of-Bag，没被抽到的样本成为测试集） 评估和特征重要性、但黑盒不可解释。

**决策树 vs 随机森林对比**：

| 维度 | 决策树 | 随机森林 |
|------|--------|---------|
| **结构** | 一棵树 | N棵树投票/取平均 |
| **方差** | 高（过拟合） | 低（多树平均降方差） |
| **偏差** | 低（树可长很深） | 低（和单棵树差不多） |
| **可解释性** | 强（可画树结构） | 弱（黑盒） |
| **稳定性** | 差（数据变一点树大变） | 好（多树平均稳定） |
| **标准化** | 不需要 | 不需要 |
| **过拟合风险** | 高 | 低 |

|  | 解释 |
|---|---------|
| 偏差 | 模型预测的"平均水平"与真实值的偏离 → 欠拟合就是偏差大（模型太简单，学不到规律） |
| 方差 | 不同训练集训练出的模型的"波动" → 过拟合就是方差大（模型对训练数据太敏感，换一批数据就变） |


## 二、Boosting（监督学习）

> **串行训练，每棵树纠正前一棵的错误（降偏差）。** 与 Bagging 的根本区别：Bagging 换数据目标不变，Boosting 数据不变换目标（残差）。

### GBDT（Gradient Boosting Decision Tree） 核心思想：拟合残差

每棵树不拟合原始标签，而是拟合前面所有树的预测残差（真实值 - 当前预测值）：

```
全部数据 -> 树1（拟合 y）            <- 原始标签
全部数据 -> 树2（拟合 残差1 = y - y_hat_1）  <- 同一批数据，目标变了
全部数据 -> 树3（拟合 残差2 = y - y_hat_2）  <- 目标又变了
```

> 残差 = MSE 损失的负梯度。GBDT = 梯度下降 + 决策树，每棵树走一步梯度下降。

**最终输出 = 加权累加**（非投票）：

```
y_hat = y_hat_0 + eta * 树1 + eta * 树2 + ... + eta * 树N
```

- 初始预测 y_hat_0（如均值）+ 每棵树乘学习率 eta 逐步累加
- 学习率小（如0.1）-> 需要更多树 -> 但泛化更好

### XGBoost（eXtreme Gradient Boosting） 相对 GBDT 的改进

> XGBoost 不是新算法，而是把 GBDT 的每一步都优化到极致。

| 改进 | GBDT | XGBoost |
|------|------|---------|
| 正则化 | 无 | 损失函数加 L1/L2 |
| 导数 | 一阶 | 一阶+二阶（收敛更快） |
| 缺失值 | 需手动处理 | 自动学习走左/右 |
| 并行 | 串行 | 特征预排序并行 |
| 稀疏感知 | 不支持 | 自动处理 |

**Bagging vs Boosting 对比**：

| 维度 | Bagging（随机森林） | Boosting（GBDT/XGBoost） |
|------|-------------------|------------------------|
| **训练方式** | 并行（树独立） | 串行（后棵纠正前棵） |
| **基模型** | 深树（低偏差高方差） | 浅树（高偏差低方差） |
| **目标** | 降方差 | 降偏差 |
| **数据** | 每棵树用不同 bootstrap 抽样 | 所有树用同一批数据，目标（残差）不同 |
| **最终输出** | 投票/平均 | 加权累加 |
| **过拟合风险** | 低 | 较高（需早停 + 正则化） |
| **异常值** | 不敏感 | 敏感（反复放大） |

## 三、LightGBM（监督学习）

> 微软开源，在 XGBoost 基础上进一步优化**速度和内存**。两个核心创新：直方图算法 + Leaf-wise 生长。

### 直方图算法（加速分裂）

> 把连续特征值离散化到桶（bin）中，每个桶存梯度统计量（一阶 G、二阶 H 之和），分裂只在桶边界尝试。

```
对于一个特征，有10000个值，分256个桶，遍历256次
精确分裂（XGBoost）：              直方图分裂（LightGBM）：

  10000个值 -> 排序 -> 遍历10000次    10000个值 -> 分256个桶 -> 遍历256次
  每次分裂重新排序                    预先分桶，不再排序
  内存：float32（4字节/样本）         内存：uint8（1字节/样本，省4倍）
```

每个桶存的内容：

```
桶号    桶内样本      G(一阶导数和)    H(二阶导数和)
桶0    [0.9, 1.2]    G0              H0
桶1    [2.1, 2.8]    G1              H1
桶2    [3.5]         G2              H2
...

分裂时用前缀和技巧，O(桶数) 一遍扫完：
  切在桶k后：左G = 桶0~k的G累加，右G = 总和 - 左G
```

> **代价**：桶内的具体值被"模糊"（只能桶边界切，不能桶内切），精度略有损失（通常 < 1%），但速度快几倍、内存省几倍。

### Leaf-wise 生长策略

> 每次只分裂**收益最大**的叶子，不管它在第几层（XGBoost 默认 Level-wise 逐层分裂）。

```
Level-wise（逐层）：              Leaf-wise（择优）：

      ●                               ●
     / \                             / \
    ●   ●                           ●   ●     <- 谁增益大选谁分裂
   /| |\ |\                         / \
  ● ● ● ● ● ●                      ●   ●      <- 继续选增益最大的
  (又宽又浅)                        / \
                                    ●  (又深又窄)

  同层全分裂，效率低                每次选最优，效率高
  但树浅，不易过拟合                但可能很深，需限制 max_depth
```

| 维度 | Level-wise | Leaf-wise |
|------|-----------|-----------|
| **分裂方式** | 同层全分裂 | 只分裂增益最大的叶子 |
| **树形状** | 均衡（宽浅） | 不对称（深窄） |
| **效率** | 低（很多无用分裂） | 高（每次都选最优） |
| **过拟合风险** | 低 | 高（需限制 `max_depth` 和 `num_leaves`） |

> **Leaf-wise 的风险**：可能生成很深的树，少量样本被分到深层叶子 -> 过拟合。必须限制 `num_leaves`（比 `max_depth` 更重要），一棵深度 d 的满二叉树有 2^d 个叶子。

## 四、CatBoost（监督学习）

> Yandex 开源，核心优势：**自动处理类别特征，不需要手动编码。**

### 问题：类别特征为什么麻烦？

决策树只能对数值做阈值分裂（`x <= 3.0?`），不能对字符串（`"北京" <= ?` 没意义）。传统编码方法都有坑：

| 方法 | 问题 |
|------|------|
| One-Hot | 类别多时维度爆炸 |
| Label Encoding | 引入虚假大小关系 |
| Target Encoding | **数据泄漏**：用了全量标签信息，训练分数虚高 |

### CatBoost 核心创新：Ordered Target Encoding

> 用标签的均值编码类别（编码值反映类别与目标的关系），但每个样本只用**之前**的同类样本算编码，避免泄漏。

```
传统 Target Encoding（有泄漏）：
  样本1: 北京, 房价500 -> 编码 = 全部北京均价 = (500+600+700)/3 = 600
  样本2: 北京, 房价600 -> 编码 = 600   <- 含样本2、3的信息！

Ordered Encoding（无泄漏）：
  样本1: 北京, 房价500 -> 之前无北京 -> 用全局先验（如575）
  样本2: 北京, 房价600 -> 之前北京: [500] -> 编码 = 500
  样本3: 北京, 房价700 -> 之前北京: [500,600] -> 编码 = 550
  
  每个样本只看"过去"，不看"未来" -> 无泄漏
```

**预测时**：用训练时学到的编码映射，不重新算（测试时没有标签）。

### 三大框架对比

| 维度 | XGBoost | LightGBM | CatBoost |
|------|---------|----------|----------|
| **核心优势** | 精度高、稳定 | 速度快、省内存 | 类别特征自动处理 |
| **类别特征** | 需手动编码 | 支持但需指定 | **全自动** |
| **生长策略** | Level-wise | Leaf-wise | Level-wise（对称树） |
| **分裂方式** | 预排序/近似 | 直方图 | 直方图 |
| **速度** | 中 | **最快** | 慢（Ordered开销） |
| **小数据** | 好 | 好 | **最好** |
| **类别特征多** | 差 | 中 | **最好** |
| **调参难度** | 中 | 中 | **低**（默认就好） |

> **选型**：类别特征多用 CatBoost，大数据多用 LightGBM，小数据/求稳定用 XGBoost。

## 五、模型融合

> 不同模型擅长不同方面，组合起来比单打独斗强。前提：模型之间要有多样性（错误模式不同）。

### 融合的三种层次

| 层次 | 方法 | 复杂度 | 效果 |
|------|------|--------|------|
| **简单融合** | 投票（分类）/ 平均（回归） | 最低 | 有提升 |
| **加权融合** | 按模型表现分配权重 | 低 | 稍好 |
| **Stacking/Blending** | 用元模型从数据中学习如何组合 | 高 | **最好** |

**简单融合**：少数服从多数，人定的规则。

```
模型A: 预测猫    模型A: 500万
模型B: 预测猫    模型B: 520万   -> 平均: 510万
模型C: 预测狗    模型C: 510万
-> 投票: 猫(2票)
```

**加权融合**：按模型准确率分配权重，好的模型说话权更大。

```
模型A(准确率85%): 预测猫   ─ 权重0.2
模型B(准确率88%): 预测狗   ─ 权重0.5  -> 加权结果: 狗
模型C(准确率90%): 预测猫   ─ 权重0.3
```

**Stacking/Blending**：投票和加权的规则都是人定的，元模型从数据中自动学习"什么时候信谁"。

```
第一层（基础模型）：           第二层（元模型）：
  LR  -> 预测1                 [LR预测, RF预测, XGB预测] -> 元模型 -> 最终预测
  RF  -> 预测2                 
  XGB -> 预测3                 元模型学习：RF和XGB都预测高 -> 判正类
                               LR预测高但XGB预测低 -> 判负类（信XGB）
```

> **为什么需要元模型？** 投票/加权是"人定的规则"，没有从数据中学习。元模型从数据中自动学出最优组合方式，效果更好。元模型通常用简单的逻辑回归即可（基础模型已做了复杂工作，元模型只需学组合）。

### Stacking

> 用元模型从数据中学习"怎么组合基础模型的预测"。关键：用 K 折交叉验证生成元特征，避免数据泄漏。

#### 为什么不能直接用训练集预测？

> 基础模型在训练集上训练，又用同一个训练集的预测训练元模型 -> 元模型看到的是过拟合的虚高预测 -> 学到"无脑相信基础模型" -> 测试翻车。

#### K 折交叉验证生成元特征（以 K=3、3个基础模型为例）

```
训练集（9个样本）分3折：
  折A: 样本1,2,3   折B: 样本4,5,6   折C: 样本7,8,9

第一轮：用折B+折C训练 -> 预测折A（模型没见过折A）
  样本1: [LR=0.8,  RF=0.9,  XGB=0.85]
  样本2: [LR=0.3,  RF=0.2,  XGB=0.4]
  样本3: [LR=0.7,  RF=0.6,  XGB=0.8]

第二轮：用折A+折C训练 -> 预测折B
  样本4: [LR=0.1,  RF=0.2,  XGB=0.15]
  样本5: [LR=0.6,  RF=0.7,  XGB=0.5]
  样本6: [LR=0.9,  RF=0.85, XGB=0.95]

第三轮：用折A+折B训练 -> 预测折C
  样本7: [LR=0.4,  RF=0.5,  XGB=0.45]
  样本8: [LR=0.8,  RF=0.7,  XGB=0.85]
  样本9: [LR=0.2,  RF=0.3,  XGB=0.25]
```

> 每个样本的元特征都是"没见过它的模型"给的预测（out-of-fold），真实可靠，没有过拟合。

#### 拼成元特征矩阵，训练元模型

```
元特征矩阵（9×3）：          真实标签：
样本  LR_pred  RF_pred  XGB_pred  |  y
────────────────────────────────|─────
1     0.80     0.90     0.85      |  1
2     0.30     0.20     0.40      |  0
...                              | ...
9     0.20     0.30     0.25      |  0

元模型（逻辑回归）用这个矩阵 + 真实标签训练
-> 学到：RF和XGB都高 -> 判正类；LR高但XGB低 -> 判负类
```

#### 最终预测流程

```
1. 用全部训练数据重新训练基础模型（交叉验证的模型丢掉，只是为了生成元特征）
2. 新样本进来：
   3个基础模型各自预测 -> [0.75, 0.85, 0.80]
   元模型接收 -> 最终预测 -> 正类
```

### Blending

> Stacking 的简化版：用 holdout 集代替 K 折交叉验证，更简单快但数据利用率低。

#### holdout 集怎么产生

> 从训练集中随机划出一小部分（10%~20%）"扣留"，基础模型不用它训练，专门用来生成元特征。

```
训练集（1000个样本）
├── 训练子集（800个, 80%）  <- 训练基础模型
└── holdout集（200个, 20%） <- 生成元特征，训练元模型
```

#### 完整流程

```
Step 1: 训练集划分为 训练子集(80%) + holdout集(20%)
Step 2: 用训练子集训练3个基础模型（LR、RF、XGB）
Step 3: 基础模型预测 holdout集 -> 生成元特征（200×3矩阵）
Step 4: 元模型用元特征 + holdout真实标签训练
Step 5: 预测：新样本 -> 3个基础模型预测 -> 元模型 -> 最终预测
```

> **vs Stacking 的关键区别**：Stacking 用 K 折让所有样本都有元特征，Blending 只有 holdout 部分有元特征。基础模型只训练 1 次（Stacking 要 K 次），快但元模型训练数据少。

#### Stacking vs Blending

| 维度 | Stacking | Blending |
|------|---------|---------|
| **元特征生成** | K 折交叉验证 | holdout 集（划分一份出来） |
| **元模型训练数据** | 全部样本 | 仅 holdout 部分 |
| **数据利用率** | 高 | 低 |
| **计算量** | 大（K 倍训练） | 小（1 倍） |
| **稳定性** | 高 | 较低 |
| **适用** | 数据多、竞赛 | 数据少、快速原型 |

> **基础模型要有多样性**：LR（线性）+ RF（Bagging）+ XGB（Boosting）是经典组合，错误模式不同，融合提升大。元模型越简单越好（逻辑回归即可）。
