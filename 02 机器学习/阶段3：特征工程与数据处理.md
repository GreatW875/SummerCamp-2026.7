# 阶段三：特征工程与数据处理

> **一句话总纲**：模型是锅，特征是米——"巧妇难为无米之炊"。特征工程决定模型的上限，模型只是逼近这个上限。

## 一、EDA（探索性数据分析）系统流程

> **本质**：像买二手房前的验房——不急着谈价（建模），先把房子里外看个遍：哪里有裂缝（缺失）、哪里被改造过（异常）、朝向和房价什么关系（相关性）。**看清数据，再决定怎么用它。**

### 五步走流程

```
① 全局概览 → ② 目标变量 → ③ 单变量 → ④ 双变量关系 → ⑤ 缺失与异常
（先看小区）   （先看房价）  （逐间房看）  （房间之间的关系）  （找毛病）
```

### ① 全局概览：拿到数据先"称体重、量身高"

```python
df.shape        # 多少行多少列 → 房子多大
df.dtypes       # 每列什么类型 → 哪些是数值、哪些是类别
df.head()       # 前几行长啥样 → 开门第一印象
df.describe()   # 均值/极值/分位数 → 体检基础指标
```

> 类比：拿到体检报告，先看身高体重年龄等基本信息，建立整体印象。

### ② 目标变量分析：先搞清楚"要预测的对象"

```python
sns.histplot(df['SalePrice'], kde=True)
df['SalePrice'].skew()   # 偏度：尾巴往哪边拖
```

> 类比：看病先确认"病人哪里不舒服"。房价往往**右偏**（少数豪宅拖着长尾巴）→ 直接决定后面要做 `log1p` 变换。

### ③ 单变量分析：逐个特征"单独审问"

| 特征类型 | 看什么 | 画什么图 |
|---|---|---|
| 数值型 | 分布形状、偏斜、异常点 | 直方图、箱线图 |
| 类别型 | 各类别占比、是否失衡 | 柱状图（countplot） |

### ④ 双变量分析：找"谁和目标有关系"

```python
corr = df.corr(numeric_only=True)
sns.heatmap(corr)                                        # 相关性热力图
sns.scatterplot(x='GrLivArea', y='SalePrice', data=df)   # 散点图
```

- **特征 vs 目标**：相关性高 → "重点嫌疑人"（重点特征）
- **特征 vs 特征**：相关性 0.9+ → 信息重复（共线性），可删一个

> 类比：侦探画人物关系图——谁和受害者（房价）关系密切，谁和谁是同伙（冗余特征）。

### ⑤ 缺失与异常：专找"数据里的坑"

**缺失先分三种情况**（决定怎么处理，不能一上来就补）：

| 类型 | 含义 | 例子 | 对策 |
|---|---|---|---|
| **MCAR** 完全随机 | 纯属手滑 | 录入员漏填 | 直接补均值/中位数 |
| **MAR** 有条件随机 | 缺失与其他特征有关 | 豪宅不愿报面积 | 用其他特征预测来补（KNN 插补） |
| **MNAR** 非随机 | 缺失本身携带信息 | 没车库 → 车库面积为空 | **不补！缺失即信息**，填 "None" 或单独成类 |

**异常值两板斧**：

| 方法 | 规则 | 适用 |
|---|---|---|
| 3σ 原则 | 偏离均值 3 个标准差之外 | 要求数据近正态 |
| IQR 法 | 超出 $Q1 - 1.5 \times IQR$ 或 $Q3 + 1.5 \times IQR$ | 更稳健，不假设分布 |

> IQR 类比：看班级成绩——中间 50% 的"中等生"范围是正常区间，离区间太远的分数值得怀疑。

### EDA 的产出：一份"待办清单"

EDA 不是为了画图好看，而是产出**可执行的处理清单**。以 House Prices 为例：

1. 目标变量 SalePrice 右偏 → 待办：`log1p` 变换
2. `GrLivArea` 与房价相关 0.7+，但右下角有异常大房子 → 待删
3. `PoolQC` 缺失 99% → 缺失即"没泳池"，填 None
4. 两个车库特征相关 0.88 → 留一个

### 附：特征编码速查表（One-hot / Ordinal / Frequency / Target）

> 模型只吃数字。编码 = 把类别翻译成数字的四种译法。

| 编码 | 做法 | 类比 | 适用 | 坑 |
|---|---|---|---|---|
| **One-hot** | 每类开一列，属于=1 否则=0 | 选票打勾，彼此平等 | 无序 + 类别少（<20） | 类别多 → 维度爆炸 |
| **Ordinal** | 按序映射 1, 2, 3… | 学历编号，大小即程度 | **有序**类别（S/M/L） | 无序乱编号 = 捏造假大小关系 |
| **Frequency** | 类别 → 出现次数 | 不看店名看排队人数 | 高基数 + 频率有信息 | 频率相同的类别无法区分 |
| **Target** | 类别 → 该类目标均值 | 学校历年升学率 | 高基数，榨干信息量 | **必须 K 折防泄漏**（考点） |

**Target Encoding 为什么过拟合 + 怎么防（学习目标 1）**：

- **坑**：某类别只有 1 个样本时，编码值 = 它自己的目标值 → 等于抄答案，训练神勇、测试翻车
- **K 折实现**：每折用【其他 K-1 折】算目标均值，映射当前折（本人成绩不参与自己的编码）；测试集用全部训练集映射（天然合法）
- **平滑**：样本少的类别向全局均值收缩，不信小样本
- 口诀：有序用序号，量少用独热，量大用频率，榨信息用目标——**目标编码必配 K 折**

## 二、特征变换（log / Box-Cox / Yeo-Johnson）

> **本质**：线性模型假设数据像"匀称的钟形曲线"，就像标准螺丝刀只能拧标准螺丝。房价这类右偏长尾数据是"异形螺丝"——**变换就是把螺丝修圆。**

### 变换的目标：把数据"整训成标准士兵"

| 目标 | 变成什么样 | 手段 | 受益模型 |
|---|---|---|---|
| ① 形状对称 | 偏度 ≈ 0 的钟形（近正态） | log / Box-Cox / YJ | LR、SVM、KNN |
| ② 尺度统一 | 均值 0、方差 1（同一"货币"） | 标准化 / 归一化 | 梯度下降类、距离类 |
| ③ 误差稳定 | 百分比误差恒定（同方差） | 对 y 取 log | 所有回归模型 |

- **为什么模型喜欢正态？** 最小二乘法 = "误差服从正态分布"假设下的最优解。数据正态 → 假设成立 → 预测准。
- **为什么要统一尺度？** 尺度一致 → 梯度下降等高线是圆形 → 直指圆心；尺度悬殊 → 扁椭圆 → 来回震荡如"醉汉下山"。
- **为什么要稳定误差？** 房价误差随价格等比放大（20 万房差 5 万、200 万房差 50 万），模型被大房子"绑架"。取 log 后误差变百分比，大户小户一视同仁——这就是 House Prices 比赛用 **RMSLE** 的原因。

### 三种变换对比

| 方法 | 直觉 | 数据要求 | 特点 |
|---|---|---|---|
| **对数变换** `log1p` | 把"绝对差"变"倍数差" | x > -1 | 最简单，手工首选；`+1` 兼容 x=0 |
| **Box-Cox** | 自动寻优 λ 的变换族 | **必须严格正数** | λ=0 退化为 log；λ=1 不变换；λ=0.5 开平方 |
| **Yeo-Johnson** | Box-Cox 升级版 | **支持零和负数** | sklearn 推荐默认 |

**Box-Cox 公式**：

$$y^{(\lambda)} = \begin{cases} \dfrac{x^\lambda - 1}{\lambda} & \lambda \neq 0 \\ \ln x & \lambda = 0 \end{cases}$$

> **类比**：自动调焦眼镜——不用手猜度数 λ，算法自动找到"最清晰"（最接近正态）的一档。Yeo-Johnson 是升级版镜片：负数也能配。

```python
from sklearn.preprocessing import PowerTransformer
pt = PowerTransformer(method='yeo-johnson')   # 默认 YJ，无需纠结正负
X_transformed = pt.fit_transform(X)
```

**对数变换的直觉**：工资 1 千 → 2 千（翻倍）和 100 万 → 100.1 万（零头），绝对差同为 1 千，意义天差地别。log 后差距反映**倍数**而非绝对值。

### 关键：不是所有模型都需要变换

| 模型 | 特征变换 | 原因 |
|---|---|---|
| LR / SVM / KNN | **需要** | 基于距离与正态假设，怕偏态和量纲 |
| 树模型（RF/XGB） | **不需要** | 树按排序找切分点，单调变换排序不变 → 切分结果一样 |

> **类比**：树模型像"按身高排队分班"，身高从厘米换成英寸（单调变换），队伍顺序纹丝不动。
> **但**：对目标变量 y 做 log 变换对树模型**依然有用**——MSE 会被天价豪宅主导，log 后模型不再只顾"伺候大户"。

## 三、特征构造与交互：1+1 > 2

> **类比**：做菜——原始特征是土豆、牛肉、咖喱，构造就是把它们做成"咖喱牛肉"。单个原料信息有限，组合才有灵魂。

### House Prices 经典构造套路

| 类型 | 例子 | 直觉 |
|---|---|---|
| **加和** | `TotalSF = 地下室 + 一楼 + 二楼` | 买家看总面积，没人分开算 |
| **时间差** | `房龄 = 销售年份 - 建造年份` | "几岁"比"哪年生"更影响价格 |
| **比率** | `平均每房面积 = 总面积 / 房间数` | 同样 100㎡，3 房和 6 房天壤之别 |
| **乘法交互** | `质量分 × 总面积` | 好质量+大面积 = 溢价**相乘**而非相加 |

### 为什么交互项有效？

> 线性模型只会算"加法账"：价格 = a×质量 + b×面积。现实是**乘法账**——好质量让每平米更值钱，面积越大质量总溢价越高。`质量×面积` 交互项把这种协同效应喂给模型。

**铁律：消融实验验证**——加入构造特征前后跑交叉验证，分数涨了留、没涨删。

## 四、分箱（Binning）：把"刻度尺"变"档位"

> **类比**：风扇的无级变速（连续）vs 一二三档（分箱）；考试 0-100 分是刻度尺，"优良中差"是档位。

### 三种分法

| 方法 | 做法 | 适用 |
|---|---|---|
| **等宽** `pd.cut` | 按值域均分 | 分布均匀时 |
| **等频** `pd.qcut` | 每箱装同样多样本 | 偏态数据首选 |
| **业务规则** | 房龄：0-5 新房 / 5-15 次新 / 15+ 老房 | 有领域知识时最香 |

### 什么时候有用？

1. **关系非线性时**：年龄 vs 收入是"倒 U 型"，直线学不会拐弯；分箱后每段各自拟合 → 拐弯解决
2. **抗异常值**：500 万和 5000 万豪宅进同一个"豪宅箱"，极端值不再捣乱

> **类比**：地图等高线——海拔 500m 和 520m 染成同色块，细微差别被抹平，大局观反而清晰。

**代价**：损失精度。树模型自己会找最优切点（智能分箱），所以**分箱主要服务线性模型**，给 XGBoost 用是多此一举。

### 对症下模型速查

| 技术 | 服务谁 | 一句话 |
|---|---|---|
| log / Box-Cox / YJ | LR、SVM、KNN | 掰正歪分布，树模型免了 |
| 特征组合/交互 | **所有模型** | 通用增益，但要消融验证 |
| 分箱 | 线性模型 | 帮直线学会"拐弯" |

## 五、特征选择（Filter / Wrapper / Embedded）

> **总类比**：球队裁员。怎么裁，决定了三种流派。

| 流派 | 类比 | 做法 | 优点 | 缺点 |
|---|---|---|---|---|
| **Filter** 过滤法 | **看简历筛** | 不看配合，只看单项指标 | 极快，训练前完成 | 不知"岗位匹配度"，易误删 |
| **Wrapper** 包装法 | **试用期考核** | 实际训模型决定去留（RFE） | 最准 | 每删一个重训一次，极慢 |
| **Embedded** 嵌入法 | **绩效考核自动末位淘汰** | 训练中模型自己打分 | 性价比最高 | 依赖模型的打分机制 |

### Filter 过滤法：训练前独立打分

| 方法 | 看什么 | 直觉 |
|---|---|---|
| 方差阈值 | 特征自身方差 | 大家都考 90 分的科目没有区分度 |
| 相关系数 | 与目标的线性相关 | 和房价无关的特征删掉 |
| 卡方检验 | 类别特征与类别目标的独立性 | "颜色"和"是否违约"有关系吗 |
| 互信息 | 任意形式相关（含非线性） | 比相关系数眼更尖 |

> 特点：只看特征与目标的"单线联系"，**不看特征间的配合**——两个冗余特征可能双双被留下。

### Wrapper 包装法：RFE 递归特征消除

```
全部特征 → 训练 → 删最弱的 1 个 → 重训 → 再删 → ... → 剩 N 个
```

> 末位淘汰制选秀：每轮淘汰最差选手，**重新组队再打一场**。准，但 50 个特征要训 50 次。

### Embedded 嵌入法：训练时顺手完成

- **L1（Lasso）**：惩罚把不重要特征系数**压成 0** → 非零系数特征自动胜出
- **树模型重要性**：分裂贡献越大分数越高

```python
SelectFromModel(Lasso(alpha=0.001)).fit(X, y)                     # L1 筛
SelectFromModel(RandomForestRegressor(), threshold='median').fit(X, y)  # 树重要性筛
```

> **实战建议**：Filter 粗筛（砍明显垃圾）→ Embedded 精筛；Wrapper 只在特征少（<50）时用。

## 六、类别不平衡处理（SMOTE / Class Weight）

> **为什么 Accuracy 是骗局**：100 万件行李里 10 件危险品，安检全部放行也有 99.999% 准确率——但危险品全进去了。

### SMOTE：给少数类"造人"

不是复制，而是**在少数类样本之间"杂交"**：

```
对少数类样本 x：找 k 个近邻（同为少数类）→ 随机选一邻居 → 两点连线上随机取点 = 新样本
```

> **类比**：两个村民特征取中间值，虚拟出"混血"新村民——不是克隆，增加了多样性。

```python
from imblearn.over_sampling import SMOTE
X_res, y_res = SMOTE(random_state=42).fit_resample(X_train, y_train)
```

> **警告**：SMOTE **只能用在训练集**！先 SMOTE 再划分 = 同一"家族"样本同时进训练和测试 → 泄漏，分数虚高。

### Class Weight：给少数类"加话语权"

不改数据，改**犯错代价**——错杀少数类的惩罚放大 N 倍：

```python
LogisticRegression(class_weight='balanced')   # 权重 = 类别频率反比
```

> **类比**：法院量刑——错放危险品的罪责远大于误查普通行李，模型宁可多报警。

### 怎么选？

| 场景 | 建议 |
|---|---|
| 样本充足 | Class Weight 优先（一行代码，不造数据） |
| 少数类极少（几十条） | SMOTE（权重再大数据也不够学） |
| 树模型 | Class Weight（SMOTE 的"中间点"对树切分帮助有限，可能落在无意义区域） |

> 配套：不平衡数据评估用 **PR-AUC / F1**，不看 Accuracy（S4 详讲）。

## 七、Pipeline + ColumnTransformer：防泄漏的"流水线工厂"

### Pipeline 是什么？

sklearn 的**链条容器**：把 N 个预处理步骤 + 1 个模型按顺序串成一个对象，对外只暴露 `fit` / `predict`。

```python
pipe = Pipeline([
    ('imputer', SimpleImputer(strategy='median')),  # 工序1：缺失值填充
    ('scaler', StandardScaler()),                   # 工序2：标准化
    ('model', LogisticRegression())                 # 工序3：模型
])
```

> **类比**：麦当劳厨房流水线——面包进、汉堡出，顾客只对着出餐口（`predict`），不关心里面工序顺序。

### 内部机制（关键）

```
【训练】pipe.fit(X_train, y)
  X ──fit_transform──→ [imputer：算出并"记住"中位数] ──→ X1
    ──fit_transform──→ [scaler：算出并"记住"均值/方差] ──→ X2
    ──fit────────────→ [model：学习权重]

【预测】pipe.predict(X_new)
  X_new ──transform──→ [imputer：套用训练记住的中位数] ──→ X1
        ──transform──→ [scaler：套用训练记住的均值/方差] ──→ X2
        ──predict────→ [model]
```

**核心规则**：训练时 `fit_transform`（学参数+应用）；预测时只 `transform`（套旧参数），**绝不重新 fit**。

> **类比**：料理包——中央厨房（训练）调好配方（记住的参数），门店（预测）只按配方复热，**不许重新调味**。

### 四大作用

| 作用 | 说明 | 类比 |
|---|---|---|
| ① 防泄漏 | `cross_val_score(pipe, X, y, cv=5)` 每折只在训练折 fit 预处理 | 5 次模拟考，次次真闭卷 |
| ② 保一致 | 预测自动套训练参数，不可能漏步骤/用错模式 | 全国门店一个味 |
| ③ 可搜索 | `param_grid={'imputer__strategy': [...]}` 双下划线穿透子步骤，预处理选择也成超参 | 配方本身也能优化 |
| ④ 易部署 | `joblib.dump(pipe)` 预处理+模型一个文件打包 | 料理包整包配送 |

### ColumnTransformer 的分工

| | 管什么 | 类比 |
|---|---|---|
| **ColumnTransformer** | **横向分流**：不同列走不同处理 | 医院分诊台：数值列送内科、类别列送外科 |
| **Pipeline** | **纵向串联**：步骤先后执行 | 就诊全流程：先挂号（预处理）再看诊（模型） |

```python
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.pipeline import Pipeline
from sklearn.linear_model import Ridge

num_pipe = Pipeline([('imputer', SimpleImputer(strategy='median')),
                     ('scaler', StandardScaler())])
cat_pipe = Pipeline([('imputer', SimpleImputer(strategy='most_frequent')),
                     ('onehot', OneHotEncoder(handle_unknown='ignore'))])
preprocessor = ColumnTransformer([('num', num_pipe, num_cols),
                                  ('cat', cat_pipe, cat_cols)])
full_pipe = Pipeline([('prep', preprocessor), ('model', Ridge())])
cross_val_score(full_pipe, X, y, cv=5)   # 每折内部先 fit 预处理，天然防泄漏
```

### 一图看懂 Pipeline 与 ColumnTransformer 的关系

```
┌───────────────────────────── Pipeline（纵向串联：时间轴）─────────────────────────────┐
│                                                                                       │
│                ┌────────── ColumnTransformer（横向分流：空间轴）──────────┐            │
│                │                                                          │            │
│                │   数值列 ──→ num_pipe（填中位数 → 标准化）──┐             │            │
│  原始数据表    │                                             ├─→ 汇合拼接 ─┼──→ 模型 ──→ 预测
│  ───────────→  │   类别列 ──→ cat_pipe（填"None" → One-hot）─┘  （一张大矩阵） (Ridge)   │
│     X          │                                                          │            │
│                │   未认领列 ──→ remainder='drop'（丢弃，默认）              │            │
│                └──────────────────────────────────────────────────────────┘            │
│                                                                                       │
│   【fit 录制】每站现场学参数并刻下：中位数 / 均值方差 / 类别表 / 模型权重                     │
│   【predict 回放】每站只套用旧参数，绝不重新 fit                                          │
└───────────────────────────────────────────────────────────────────────────────────────┘

  外层 Pipeline：决定"先做什么后做什么"（串联）
  内层 ColumnTransformer：决定"哪列走哪条路"（分流 → 汇合），是 Pipeline 的第一站
```

> **读图要点**：ColumnTransformer 不是与 Pipeline 平行的另一套系统，而是**嵌在 Pipeline 里当第一站**——分拣中心（横向分流）先把不同材质的原料各自加工、汇成标准件，再沿流水线（纵向串联）流向大厨。
